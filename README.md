# چت‌بات workflow نگهداری و تعمیرات تجهیزات خودرویی

یک چت‌بات آموزشی که یک **workflow واقعی و صریح** را نشان می‌دهد:
ثبت تجهیز، بازدید، ارزیابی، خرابی، درخواست تعمیراتی، تایید و حکم کار —
با **tool calling، مدیریت توکن، compaction و eval با LangSmith.**

همه‌چیز ساده و قابل خواندن است؛ هر فایل یک کار مشخص می‌کند.
رکوردها در دیتابیس **SQLite** ذخیره می‌شوند (فایل `data/maintenance.db`)
و با خاموش شدن برنامه پاک نمی‌شوند.

> برای یادگیری قدم به قدم، اول بخوان: [`docs/LEARN_FA.md`](docs/LEARN_FA.md)

## مراحل workflow

```
ثبت تجهیز (EQ-001)
      ↓  با شماره پلاک
ثبت بازدید (INSP-001)
      ↓  بر اساس زیرمجموعه: موتور، چرخ و...
ثبت ارزیابی (EV-001)
      ↓  می‌تواند بدون خرابی باشد
ثبت خرابی (FLT-001)  ← اختیاری، وصل به یک ارزیابی
      ↓
ثبت درخواست تعمیراتی (REQ-001)
      ↓  قبل از ثبت، پنجره تایید: اول گزارش بازدید، بعد تجهیز و خرابی را تایید یا رد کن
تایید درخواست
      ↓
ثبت حکم کار (WO-001)
         تعمیرگاه + قطعات مورد نیاز
```

هر مرحله یک شماره رهگیری می‌دهد و قدم بعدی را نمی‌توان
قبل از قدم قبلی انجام داد (مثلا حکم کار بدون تایید درخواست ثبت نمی‌شود).

قبل از ثبت درخواست تعمیراتی، یک پنجره تایید باز می‌شود که اول گزارش بازدید
و بعد تجهیز و خرابی را نشان می‌دهد؛ درخواست فقط بعد از تایید کاربر ثبت می‌شود.
پنجره تایید «خودکار» باز می‌شود: بعد از ثبت خرابی، یا بعد از ثبت بازدید وقتی
خرابی بدون درخواست هست — بدون اینکه مدل در چت سوال بله/خیر بپرسد.
یک بار تایید کافی است و دوباره سوال نمی‌شود. ثبت خرابی هم ساده است:
شرح کوتاه کاربر کافی است و علت یا جزئیات پرسیده نمی‌شود.

## ساختار پروژه

```
vehicle-maintenance-workflow/
├── main.py                  # شروع برنامه: python main.py
├── api.py                   # API برای Angular (چت + گریدها + نمودار ماژول‌ها)
├── maintenance/
│   ├── config.py            # خواندن کلیدها از .env
│   ├── llm.py               # اتصال به مدل (توکن هاربور)
│   ├── memory.py            # شمارش توکن + compaction
│   ├── db.py                # اتصال و ساختار دیتابیس SQLite
│   ├── store.py             # رکوردها (همان تابع‌های قدیمی، روی SQLite)
│   ├── seed.py              # داده نمایشی اولین اجرا
│   ├── workflow.py          # مراحل صریح workflow + کنترل ترتیب
│   ├── tools.py             # ابزارهای مدل (13 ابزار)
│   └── chat.py              # حلقه اصلی چت + SYSTEM_PROMPT
└── evals/
    ├── langsmith_eval.py    # اجرای تست‌ها و ثبت در LangSmith
    └── test_cases.json      # سوال‌های تست
```

## نصب و اجرا (5 دقیقه)

```bash
# 1) نصب
python -m venv .venv
source .venv/bin/activate   # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt

# 2) تنظیم کلیدها
cp .env.example .env
# حالا .env را باز کن و پر کن:
# TOKEN_HARBOR_API_KEY و LLM_BASE_URL از پنل توکن هاربور
# TAVILY_API_KEY از سایت Tavily (رایگان)
# LANGSMITH_API_KEY از سایت LangSmith (رایگان، اختیاری)

# 3) اجرا — نسخه ترمینالی
python main.py
```

بعد در ترمینال بنویس، مثلا:
> یک خودروی پراید با پلاک 12ب345 ایران 67 ثبت کن

> خودروی پراید پلاک 12ب345 ایران 67 موتورش صدای غیرعادی می‌دهد

## رابط کاربری Angular + API پایتون

```bash
# ترمینال 1 — بک‌اند پایتون
python -m uvicorn api:app --reload --port 8000

# ترمینال 2 — فرانت‌اند Angular
cd frontend
npm install
npm start
# بعد باز کن: http://localhost:4200
```

همه کارها با چت انجام می‌شود؛ هیچ فرم ورودی نیست.
گریدها فقط رکوردها را نشان می‌دهند و آیکن نمودار، ماژول‌ها را جداگانه نشان می‌دهد.
رابط کاربری ۴ تب دارد: **خانه** (لندینگ با نمایشگر سه‌بعدی واقعی خودرو
— مدل GLB با Three.js، چرخش ۳۶۰ درجه با درگ، زوم و نمای منفجرشده قطعات؛
اگر مدل لود نشد گردونه عکس جای آن می‌آید — به‌علاوه آمار زنده و مراحل کار)،
**گاراژ** (لیست تجهیزها با تصویر ثابت دنا پلاس؛ تصویر هر کارت از روی نام خودرو
انتخاب می‌شود: سمند `samand.jpg`، پراید `pride.jpg`، تارا `tara.jpg`، دنا `dena-plus.jpg`،
پارس و بقیه `pars.jpg` — فایل‌ها در `frontend/public/` هستند. با کلیک روی هر خودرو، مودالش سوابق بازدید،
ارزیابی، خرابی، درخواست و حکم کار آن خودرو را نشان می‌دهد و دکمه‌های ثبت،
به چت‌بات می‌روند با پیام آماده — بدون فرم. بازدید و ارزیابی یک دکمه مشترک
دارند: «ثبت بازدید و ارزیابی»)، **چت‌بات** و **سرچ مقاله** (چت جدا با هیستوری جدا).
تم تیره سینمایی: بک‌گراند نزدیک مشکی (`#0a0a0c`) با قرمز نئون (`#e10600`)،
کارت‌های تیره و دکمه‌های گرادیان قرمز — الگو: طراحی سایت 3DTUNNERS.
نمایشگر سه‌بعدی خانه (`frontend/src/app/car-viewer.ts`) مدل `frontend/public/models/samand.glb`
را با Three.js لود می‌کند: درگ برای چرخش ۳۶۰ درجه، اسکرول برای زوم، چرخش خودکار
که موقع تعامل مکث می‌کند و دکمه «نمایش منفجرشده» که قطعه‌ها را شعاعی از هم باز می‌کند
(چرخ‌ها بیشتر بیرون می‌روند، تکه‌های بدنه به بالا). مدل، سمند X7 از Sketchfab است
([IKCO Samand X7](https://sketchfab.com/3d-models/ikco-samand-x7-free-iranian-car-ab580f4bc3c9404d8634bed918d40831)
اثر Mpgs.studio3DModels، لایسنس CC-BY-4.0 — اعتبارش زیر نمایشگر هم نوشته شده).
دانلود اسکچ‌فب یک `scene.gltf` + `scene.bin` + ۶ تکسچر بود (۳۸ مگابایت) که با
`gltfpack -cc` به یک GLB فشرده ۹٫۹ مگابایتی تبدیل شد؛ چون مدل با meshopt فشرده شده،
لودر حتما باید `MeshoptDecoder` داشته باشد (`loader.setMeshoptDecoder(MeshoptDecoder)`)
وگرنه مدل لود نمی‌شود. برای عوض کردن خودرو فقط ثابت `MODEL_URL` در `car-viewer.ts`
را عوض کن (فایل `sedan.glb` سدان تستی هم به‌عنوان یدکی در همان پوشه مانده است).
اگر مدل لود نشد، گردونه عکس جای آن می‌آید: ۷ عکس از یک دنا پلاس قرمز
(`frontend/public/turntable/dena-0001.jpg` تا `dena-0007.jpg`؛ جلو تا عقب)
که هر ۳ ثانیه با کراس‌فید عوض می‌شود و رفت و برگشت می‌چرخد؛ هاور مکث می‌کند
و درگ چپ/راست زاویه را عوض می‌کند. برای عوض کردن خودروی گردونه
فقط فایل‌های `public/turntable/` و لیست `TURNTABLE_IMAGES` در `app.ts` را عوض کن.
گوشه پایین صفحه هم یک آیکن سه‌بعدی چرخ‌دنده + آچار هست که فقط با CSS سه‌بعدی
(محورهای X و Y و Z) می‌چرخد.

## دیتابیس (SQLite)

رکوردها در یک فایل ساده ذخیره می‌شوند: **`data/maintenance.db`**
(با کتابخانه استاندارد پایتون `sqlite3`؛ هیچ پکیج جدیدی لازم نیست).
یک جدول برای هر ماژول هست: `equipment` ،`inspections` ،`evaluations` ،
`faults` ،`repair_requests` ،`work_orders` ،`pending_confirmations`
— شماره رهگیری (مثل `EQ-001`) کلید اصلی هر جدول است.

- **اولین اجرا:** جدول‌ها خودکار ساخته می‌شوند و داده نمایشی (بخش بعد)
  یک بار seed می‌شود. دفعات بعد، داده‌های قبلی سر جایشان هستند و
  شماره رهگیری از جایی که مانده ادامه پیدا می‌کند (مثلا تجهیز بعدی `EQ-004`).
- **ریست کردن:** برنامه را ببند، فایل `data/maintenance.db` را پاک کن
  و دوباره اجرا کن؛ جدول‌ها ساخته و داده نمایشی دوباره seed می‌شود.
- **دیدن داده‌ها:** با برنامه رایگان [DB Browser for SQLite](https://sqlitebrowser.org/)
  فایل را باز کن، یا در ترمینال: `sqlite3 data/maintenance.db "SELECT * FROM equipment;"`.
- **طرح:** تابع‌های `store.py` (اسم و ورودی/خروجی‌شان) دقیقاً مثل قبل‌اند؛
  فقط داخل‌شان به‌جای دیکشنری به دیتابیس حرف می‌زنند — پس `workflow.py` و
  `tools.py` و `chat.py` و `api.py` بدون هیچ تغییری کار می‌کنند.
  اتصال و ساختار جدول‌ها در `maintenance/db.py` است؛ هر عملیات اتصال
  تازه خودش را باز می‌کند و زیر یک قفل انجام می‌شود تا با چند نخ
  (thread) در FastAPI مشکلی پیش نیاید. مسیر فایل را می‌شود با متغیر
  محیطی `VEHICLE_DB_PATH` عوض کرد.
- فایل `.db` داده محلی است و روی گیت نمی‌رود (در `.gitignore` هست).

## داده نمایشی موقع اجرا

وقتی برنامه برای اولین بار اجرا می‌شود (`uvicorn api:app` یا `python main.py`)،
سه خودروی نمایشی یک بار در دیتابیس ساخته می‌شوند تا گاراژ و گریدها خالی نباشند
(`maintenance/seed.py`؛ فقط وقتی دیتابیس خالی است seed می‌شود):

- **سمند LX — پلاک 123:** دو بازدید موتور؛ خرابی سیلندر و خرابی موتور؛
  یک درخواست تعمیراتی برای خرابی موتور، در وضعیت «در انتظار تایید».
- **پژو — پلاک 456:** یک بازدید موتور بدون خرابی؛ یک بازدید چرخ با خرابی لاستیک؛
  درخواست تعمیراتی تاییدشده و حکم کار با قطعه «لاستیک بارز» و تعمیرگاه «شهید همت».
- **پراید — پلاک 789:** فقط تجهیز، بدون هیچ سابقه‌ای.

این داده‌ها در دیتابیس می‌مانند؛ با خاموش و روشن شدن برنامه پاک نمی‌شوند.

## مفاهیم، خیلی ساده

| مفهوم | کجاست؟ | یعنی چی؟ |
|---|---|---|
| **Workflow صریح** | `maintenance/workflow.py` | ترتیب قدم‌ها را ما تعیین کرده‌ایم؛ هر قدم، قدم قبلی را چک می‌کند. |
| **Tool calling** | `maintenance/tools.py` + `maintenance/chat.py` | مدل از حرف کاربر می‌فهمد کدام ابزار را صدا بزند. |
| **Token management** | `maintenance/memory.py` | توکن‌های مکالمه را می‌شمارد تا از حد نگذرد. |
| **Compaction** | `maintenance/memory.py` | وقتی توکن زیاد شد، پیام‌های قدیمی را خلاصه می‌کند. |
| **Eval با LangSmith** | `evals/langsmith_eval.py` | سوال‌های تست را می‌پرسد، امتیاز می‌دهد و در LangSmith ثبت می‌کند. |

اجرای eval:
```bash
python -m evals.langsmith_eval
```
